# R1 — Application runtime integration

## Scope
Connect runtime DB access, Next.js ingestion command/API to canonical acquisition, durable job dispatch/state, and worker handoff.

## Status
Blocked / not started. Required for real E2E; separate from deterministic S2 adapter and S3 processing implementation.

## Acceptance
- Next.js route invokes canonical acquisition boundary, not provider-specific logic.
- Runtime DB connection uses canonical schema and truthful errors.
- Acquisition and processing state survive restart/reload.
- Worker handoff is durable without Redis/Kafka/microservices.
- Fixture-only route is replaced or explicitly isolated from runtime path.

## Verification
Focused integration smoke with disposable DB and fake provider; failure scenarios for DB unavailable, malformed URL, provider unavailable, retry, and handoff loss.

## Dependencies
S1, S2
